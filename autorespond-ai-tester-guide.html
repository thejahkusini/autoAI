POST/api/auth/register
What it does: Creates a new user account. The very first account ever registered is automatically assigned the admin role. All subsequent accounts get the marketer role. Returns a JWT token immediately after registration — no separate login needed.
📥 You send: { email, password (min 6 chars), full_name }
❓ Is email already registered?
YES — Duplicate
❌ 400 — "Email already registered"
NO — Continue
✓ Proceed
❓ Is this the first user in the system?
YES
Role = "admin"
NO
Role = "marketer"
Hash password with PBKDF2-SHA256 (200,000 iterations) → save to DB
✅ Return { token (JWT), user: { id, email, full_name, role } } — HTTP 200
POST/api/auth/login
What it does: Authenticates a user and returns a JWT token valid for 480 minutes (8 hours) by default.
📥 You send: { email, password }
❓ Email found AND password matches?
NO
❌ 401 — "Incorrect email or password"
YES
✅ Return { token, user } — HTTP 200

POST/api/campaigns/{id}/generate-content
What it does: Runs the LangGraph campaign_graph workflow: (1) retrieves product context from ChromaDB, (2) calls the LLM to generate marketing copy, (3) validates the content — auto-appends opt-out text, checks channel length limits. In mock mode, returns template text instantly.
📥 You send: POST to /api/campaigns/{id}/generate-content (no body needed)
LangGraph Step 1 — RAG: Search ChromaDB for product facts (k=5 chunks)
LangGraph Step 2 — LLM: Generate campaign copy using context + objective + audience
LangGraph Step 3 — Validate: Auto-append "Reply STOP to opt out" if missing

✓ No warnings

✅ Return { content, warnings[] } — HTTP 200
POST/api/campaigns/{id}/approve
What it does: Marks campaign content as approved for launch. Content must be non-empty. Records an audit log entry. After approval, any content edit will reset the status back to "draft".
POST/api/campaigns/{id}/launch
What it does: Dispatches the campaign to all eligible customers (consent=true AND unsubscribed=false). Runs asynchronously via BackgroundTasks (or Celery if enabled). Consent and opt-out are re-checked for each customer at send time.

❓ Campaign status = "approved"?

❌ 400 — "Approve the campaign content before launching"
YES
✓ Continue
❓ At least 1 customer with consent=true AND unsubscribed=false?
NO
❌ 400 — "No eligible customers: add customers who have given consent"
YES
✓ Dispatch in background
For each eligible customer → send via email/whatsapp/sms → save Message record to DB
✅ Return { status: "launching", eligible_customers: N } — HTTP 200
